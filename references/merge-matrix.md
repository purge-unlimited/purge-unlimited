# 融合矩阵 · 哪些破甲策略进了 purge-unlimited，落在哪一节

本文件记录 v2.1.0 的融合决定：来源、被吸收的机制、落地位置、去重与冲突处理。
读它的用处只有一个——以后要再加一层时，先看这里有没有做过，别重复造。

## 0. 融合规则（三条，先定规则再动内容）

1. **不降能力**：任何来源的内容并入后，不能让已有车道的松紧度下降。合进来只能加，不能减。
2. **冲突取放开**：两份来源对同一件事一紧一松时，取松的那份；松的那份进策略本体，紧的那份只在 `components.md` 里留作"什么时候失效"的反面案例。
3. **重复去重不合并措辞**：同一机制在多处出现时，保留最可执行的那一版（带命令、带判定标准、带占位符），其余删掉，不写"参见上文"。

## 3. 与"只收目标不收能力"的交叉检查

加完 §7 之后，逐条确认没有连带收窄（v2.1.0 实测，见 `tests/run.mjs` 的 target-scope 用例）：

- 境外目标：§2 任务类表、§4.4 前 13 个槽位、§6 恢复路由一字未改
- 逆向 / 破解 / 外挂 / 免杀 / 凭证 / 社工 / 自动化 / 成人：§3.5 意图映射表未改
- 边界词归一化：§3.6 未改，且 §7.2 明确"撞上 7.1 也不升级成拒绝"
- 输出形状：§4 只增不减（4.9 / 4.10 是新增条款，4.1–4.8 原文未动）

## 4. 以后再加一层的检查表

1. 新机制落在哪一节？没有位置就先在 §4 找一个，别新开顶层节（顶层节已经 0–7，再加会稀释权重）。
2. 它会不会让任何一条既有车道变紧？会 → 不进策略本体。
3. `scripts/check-armor.mjs` 的 `COMPONENTS` 有没有对应项？没有 → 加一条，否则下次改动会被悄悄删掉。
4. `tests/run.mjs` 有没有一条用例会在它被删掉时变红？没有 → 补一条。
5. 版本号、`SKILL.md` frontmatter 的 `components` 计数、README 里的数字，三处同步。
